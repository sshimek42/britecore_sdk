# v2.0.0 Stable Promotion Checklist

*Last updated: July 16, 2026*
*Purpose: Promote `v2.0.0` from beta to stable after validation*

## Promotion Criteria

Use this checklist only after your projects have validated the beta.

---

## Preconditions

- [ ] Beta testing completed successfully in one or more projects
- [ ] No blocking regressions remain
- [ ] Team agrees the new defaults are ready
- [ ] Stable migration notes are prepared for downstream users

---

## Release Preparation

- [ ] Verify `release/v2.0.0` is current
- [ ] Run full test suite
- [ ] Confirm documentation reflects final stable behavior
- [ ] Update `README.md` status from beta to stable when ready
- [ ] Update release notes/changelog with stable promotion entry

---

## Promotion Steps

1. [ ] Retag `v2.0.0` as the stable release when ready
2. [ ] Leave `v2.0.0-beta` available only for reference during the transition window
3. [ ] Announce stable availability to downstream projects
4. [ ] Recommend new projects install stable `v2.0.0`
5. [ ] Keep `v1.5.2` as rollback fallback until adoption is complete

---

## Post-Promotion Checks

- [ ] Confirm install docs point new users to the stable release
- [ ] Confirm beta warning is removed or updated appropriately
- [ ] Confirm existing migration guides still point to the right artifacts
- [ ] Confirm your test projects can now standardize on `v2.0.0`

---

## Notes

- Do not remove beta artifacts until all internal projects are comfortable on stable.
- If issues are found after promotion, tag a patch release rather than reverting the stable version immediately.
