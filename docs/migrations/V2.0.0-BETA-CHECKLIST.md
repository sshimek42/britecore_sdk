*Last updated: July 16, 2026*
*Purpose: Historical reference for v2.0.0 beta validation*

## Current Stable Release

v2.0.0 is now stable and available as v2.0.1+. This archived checklist reflects rollout-time validation work for the first stable 2.x release.

**Windows (PowerShell):**

```powershell

```

**Linux/macOS (bash):**

```bash

```

Use the checks below when validating explicit-client adoption, typed responses, and related 2.0-era behavior in your own environment.

---

## Adoption Validation Checklist

### 1) Client Lifecycle Validation

- [ ] Initialize explicit clients with `BritecoreAPIClient(...).init_client()`
- [ ] Pass `client=client` to endpoint wrappers
- [ ] Verify context-manager cleanup works
- [ ] Confirm multi-site usage behaves correctly
- [ ] Confirm implicit client usage still works as expected

---

### 2) Typed Response Validation

- [ ] Verify quote responses expose typed fields
- [ ] Verify policy responses expose typed fields
- [ ] Verify contact responses expose typed fields
- [ ] Check `.raw_data` contains the original payload
- [ ] Confirm async wrappers return the same shapes as sync wrappers

---

### 3) Error Handling Validation

- [ ] Confirm `status_code` is attached to raised exceptions
- [ ] Confirm `error_code` is attached when the API returns one
- [ ] Confirm `request_id` is visible in logs and exceptions
- [ ] Confirm `raw_payload` is available for debugging
- [ ] Confirm `ValidationError.validation_errors` is populated when applicable

---

### 4) Middleware Validation

- [ ] Add `LoggingMiddleware` and confirm request/response logging
- [ ] Add `RequestIdMiddleware` and confirm correlation IDs propagate
- [ ] Add custom header injection middleware if needed
- [ ] Add timeout middleware if your project depends on custom request deadlines
- [ ] Confirm middleware order is correct in your use case

---

### 5) Pagination Validation

- [ ] Replace manual pagination loops with `iter_*()` helpers
- [ ] Confirm iterators stop at the last page
- [ ] Confirm iterators handle empty result sets gracefully
- [ ] Confirm async iterators work in your async workflows
- [ ] Confirm iterator results match the existing list endpoints

---

### 6) Compatibility Cleanup Validation

- [ ] Search for imports from `britecore_sdk.classes`
- [ ] Replace legacy import paths with `models`, `validators`, or `api.responses`
- [ ] Review any `v1` endpoint usage and keep the supported wrappers your integration still needs
- [ ] Confirm your code does not depend on removed compatibility shims

---

## Validation Complete

Once your test suite passes and the team approves the rollout work:

- [ ] Your test suite passes on v2.0.0
- [ ] Production-like test projects behave as expected
- [ ] No blocking regressions remain
- [ ] The team approves the rollout/adoption plan
- [ ] You are ready to ship the validated 2.x behavior you actually use

---
