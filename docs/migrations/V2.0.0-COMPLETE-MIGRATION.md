*Last updated: July 22, 2026*
*Document type: Archived implementation record (reference/archive)*
*Release status: Stable (v2.0.5+) — this document is historical context only*

## Overview

This archived document captures the rollout-era notes that accompanied the first stable 2.x SDK release.
It is **not** a standing requirement to perform a blanket SDK-wide "v1 to v2" migration.

Use this file when you want historical context for the 2.0.0 design work around:

1. Explicit client usage
2. Typed response models
3. Iterator-based pagination helpers
4. Compatibility cleanup for older import patterns

---

## Current Support Guidance

- `api_calls/v1` wrappers are **not** legacy by default.
- Some upstream BriteCore endpoints still use `v1` URLs and have no `v2` equivalent yet.
- Those supported `v1` wrappers remain available and should not be described as scheduled for removal merely because their path contains `v1`.
- Prefer the newer 2.x examples when they improve typing, testability, or clarity, not because every `v1`-named wrapper is obsolete.

## What Actually Changed in 2.0.0

### `britecore_sdk.classes` compatibility imports

The legacy `classes` import path was retired in favor of imports from `models` and `validators`.
That change is separate from upstream API version numbers.

**Earlier import pattern:**

```python
from britecore_sdk.classes import Quote

quote_obj = Quote(...)
```

**Current import pattern:**

```python
from britecore_sdk.models import Quote

quote = Quote(...)
```

### Explicit client pattern

2.0.0 standardized examples around explicit client ownership because it improves testability and multi-site usage.

**Earlier implicit-client pattern:**

```python
from britecore_sdk.api.api_calls import init_api_client
from britecore_sdk.api.api_calls.v2.quotes import get_quote

init_api_client(target_site="production")
quote = get_quote(quote_id="Q123")
```

**Explicit-client pattern introduced in 2.0.0:**

```python
from britecore_sdk import BritecoreAPIClient
from britecore_sdk.api.api_calls.v2 import quotes
from britecore_sdk.api.responses import QuoteResponse

with BritecoreAPIClient("production").init_client() as client:
    quote: QuoteResponse = quotes.get_quote(quote_id="Q123", client=client)
    premium = quote.premium
```

### Iterator-based pagination

2.0.0 also added iterator helpers for workloads that previously managed paging manually.

**Earlier manual pagination pattern:**

```python
from britecore_sdk.api.api_calls import init_api_client
from britecore_sdk.api.api_calls.v2.quotes import list_quotes

init_api_client(target_site="production")

page = 1
all_quotes = []
while True:
    response = list_quotes(page=page, limit=100)
    all_quotes.extend(response["data"])
    if len(response["data"]) < 100:
        break
    page += 1
```

**Iterator-based pattern introduced in 2.0.0:**

```python
from britecore_sdk import BritecoreAPIClient
from britecore_sdk.api.iterators import iter_quotes

client = BritecoreAPIClient("production").init_client()

for quote in iter_quotes(client=client):
    process_quote(quote)

all_quotes = list(iter_quotes(client=client))
```

## Supported Versioned Wrappers

The SDK may expose both `v1` and `v2` wrapper modules because the upstream API itself is versioned that way.

**Examples of supported `v1` wrappers:**

- `britecore_sdk.api.api_calls.v1.contacts`
- `britecore_sdk.api.api_calls.v1.policies`
- `britecore_sdk.api.api_calls.v1.quotes`

**Examples of `v2` wrappers:**

- `britecore_sdk.api.api_calls.v2.contacts`
- `britecore_sdk.api.api_calls.v2.policies`
- `britecore_sdk.api.api_calls.v2.quotes`

Choose the wrapper that matches the currently supported upstream endpoint and the SDK behavior you need.
Do not assume `v1` means deprecated or temporary.

## Adoption Checklist

Use this checklist only when you are actively modernizing older code:

- [ ] Replace `from britecore_sdk.classes import X` with imports from `models` or `validators`
- [ ] Move to explicit `client=` usage where it improves clarity, tests, or multi-site handling
- [ ] Adopt typed response models where available and helpful
- [ ] Replace manual pagination loops with iterator helpers when processing large result sets
- [ ] Confirm any move from `api_calls/v1.*` to `api_calls/v2.*` is backed by an actual supported upstream/API wrapper equivalent

## Common Adoption Questions

### Do I need to rewrite working code immediately?

No. Use the 2.x patterns for new examples and new development where they add value, but this document does not define a blanket rewrite requirement.

### Are `api_calls/v1` wrappers deprecated?

Not by default. They remain supported when the upstream API still exposes those versioned endpoints or when the SDK does not yet have a `v2` equivalent.

### What should I treat as the main 2.x guidance today?

Prefer:

- explicit `client=` usage for new code,
- typed response models when available,
- iterator helpers for pagination-heavy workflows,
- imports from `models` and `validators` instead of `classes`.
